Reading Time 是一款面向个人本地使用的微信读书分析应用。连接数据后，你可以查看阅读总览、分类图谱、阅读趋势、阅读演化和书架，也可以选择独立的 AI 解读，把分散的阅读记录和划线整理成一份有出处的个人报告。应用支持日间、夜间主题，以及桌面和移动端布局。

**不配置密钥也能体验：** 启动后打开内置合成示例，即可浏览完整书架、阅读演化、阅读时段、演示划线和四种预置解读。真实阅读统计需要微信读书 Key；主动生成 AI 解读还需要所选模型服务的 API Key。

## 功能亮点

| 模块 | 可以看到什么 |
| --- | --- |
| 阅读总览 | 核心阅读统计、分类图谱，以及你留下的句子 |
| 阅读趋势 | 阅读日历、月度时长、活跃天数、星期分布和累计时长 |
| 阅读演化 | 按年份查看阅读变化和兴趣迁移 |
| 阅读偏好 | 分类雷达图与树图、阅读时段、作者、出版社，以及阅读和听书分布 |
| 我的书架 | 未读、在读、读完状态，阅读进度、排序和单书详情 |
| 笔记与划线 | 划线和想法、关键词、时间线，以及有来源的原句 |
| AI 解读 | 四种彼此独立的生成模式，可自定义提示词并重试 |

图表可悬停查看来源和细节。数据不足时，页面会显示覆盖范围或空状态，不会用推算值填满图表。

## 快速开始

### 环境要求

- **Node.js 22 或更高版本**，以及 npm。
- 获取真实数据需要可用的微信读书 `wrk-…` API Key。应用不提供账号登录或 Key 签发。
- 使用 AI 解读需要所选模型平台的 API Key。

### 安装并启动

在 `reading-time` 项目目录中执行：

```sh
npm install
npm run dev
```

然后打开 **[http://localhost:3100](http://localhost:3100)**。

### 开始使用

1. 选择“探索合成示例”，或输入微信读书 Key 连接真实数据。
2. 选择最近 **12、24 或 36 个自然月**，开始分析。任务进行时可以查看进度或取消任务。
3. 浏览阅读报告，也可以在页面中切换日间和夜间主题。
4. 如需 AI 解读，先到“连接与设置”填写模型配置，再到“AI 解读”选择功能、确认发送范围并生成结果。
5. 你可以下载 JSON 留档。刷新页面后，当前报告会被清除。

## AI 解读

四项功能可以分别选择、独立生成，**不需要先生成 MBTI**。基础阅读统计也不依赖模型服务。

| 功能 | 内容 |
| --- | --- |
| MBTI 年度阅读人格 | 结合阅读行为、书目和划线，生成阅读人格肖像、年度金句、精神共鸣作家及证据列表 |
| 阅读推荐 | 分为“书架内 · 未读”“书架内 · 在读”“书架外 · 探索”，提供领读人手记和阅读锚点 |
| 个人认知图谱与暗线报告 | 跨书整理划线，呈现核心张力、防御武器和智识趣味，并附深度画像、暗线盲区及证据原句 |
| 跨书籍的想法大碰撞 | 从不同书籍中寻找“锋芒交锋”“暗夜回响”“一体两面”，呈现思想轨迹、想象对话和破局调和 |

生成结果旁提供 **“不满意？编辑提示词重试”**。你可以修改提示词，也可以恢复默认设置。重试成功后只替换当前功能的结果；如果失败或取消，则保留原结果。提示词可以改变表达方式和关注重点，但结构化输出与证据校验仍会保留。

推荐中的书架内书目会校验书籍 ID 和阅读状态；书架外推荐属于模型建议，未验证微信读书是否收录。认知图谱和跨书碰撞会保留真实划线出处，想象对话属于模型创作，不是作者原话。

### 划线很多时如何处理

认知图谱和跨书碰撞默认使用 **精选解读**，也可以切换为 **全部划线**。

| 模式 | 材料处理 | 请求规模 |
| --- | --- | --- |
| 精选解读 | 在本地扫描并按原文去重，再按书籍和时间选取代表材料；跨书碰撞还会参考词语关联候选 | 最多发送 160 条，每条保留前 600 字；认知图谱最多 5 次请求，跨书碰撞最多 4 次 |
| 全部划线 | 分批发送全部有效且去重后的划线，每条最多保留前 1,200 字 | 每批最多 40 条或 14,000 字符，请求数随材料量增加 |

两种模式最多同时执行 2 个模型请求。生成前会显示材料规模、最多请求次数和**输入 token 估算范围**；详细的材料范围可通过感叹号图标查看。

精选材料不代表模型读过全部划线；全部划线模式也不保证找出所有跨书关联。token 估算不包含模型输出和推理消耗，实际费用以服务商账单为准。划线只能说明你曾关注这些句子，不代表你认同原文观点。

## 模型配置

在“连接与设置”中选择预设，填写 Key，并确认模型名称。地址、模型和协议都可以修改。

| 服务商 | 默认 API 地址 | 默认模型 / 填写要求 | 协议 |
| --- | --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | Chat Completions |
| 火山方舟 · 豆包 | `https://ark.cn-beijing.volces.com/api/v3` | 填写已开通的模型 ID 或 `ep-…` 接入点 ID | Chat Completions |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` | Chat Completions |
| OpenAI | `https://api.openai.com/v1` | `gpt-5.4-mini` | Responses |
| 阿里云百炼 · 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | Chat Completions |
| 自定义 | 填写兼容服务地址 | 填写该服务提供的模型名称 | Chat Completions / Responses / Anthropic Messages |

预设只是为了快速填入配置，模型是否可用取决于平台控制台和账号权限。火山方舟需要手动填写模型或接入点 ID。百炼预设使用北京地域，Key 和地址必须匹配，也可以改成工作空间专属地址。切换到其他服务域名时，原来的 Key 会被清空。

自定义地址必须使用 HTTPS，并通过服务端的公网地址检查。当前不支持直接连接本机 HTTP 模型服务。

### 修改端口

默认端口为 `3100`。开发时，HMR 使用主端口加 1。端口被占用时，可以通过 `PORT` 修改。

**PowerShell：**

```powershell
$env:PORT=3200
npm run dev
```

**Bash：**

```sh
PORT=3200 npm run dev
```

### 本地生产运行

```sh
npm run build
npm start
```

构建产物位于 `dist/client` 和 `dist/server.js`。运行时需要 Node.js 与已安装的依赖，不能只将前端目录作为静态网站部署。

服务仅监听本机 `127.0.0.1`，当前面向个人本地使用。若自行改造为公开服务，需要另外实现身份验证、请求限流、出口控制与 HTTPS。

## 数据口径

- **统计周期：** 最近 N 个月包含本月，而本月仍是未结束周期。年度偏好按涉及的自然年统计，因此可能超出所选月份范围。
- **当前快照：** 书架、笔记总量和单书进度反映账户当前状态，不代表所选区间内新增或完成的数量。
- **时长来源：** 阅读时长来自接口统计，不根据笔记数量、划线或书名线索推算。
- **覆盖缺口：** 缺失值不会当作 0。部分单书读取失败时，报告会保留并说明缺口；核心月度数据失败则终止分析。
- **划线范围：** 总览最多精选展示 10 条。完整抓取的划线仍会保存在报告中，供深度 AI 解读使用。
- **关键词：** 词云使用固定的中文领域词表，不是完整中文分词，也不会拆出脱离上下文的英文单词。

- 时长的原始单位是秒。月度总量使用 `totalReadTime`，日历使用 `readTimes` 明细，页面统一显示到分钟。
- 电子书的未读、在读和读完状态由读完标记、进度及阅读记录共同判断。专辑完结不等于用户读完。
- 单书进度通过 `/book/getprogress` 获取。如果有当前章节，再通过 `/book/chapterinfo` 查询章节名。
- 只有 `/shelf/sync` 返回 `bookProgress[].readingTime` 时，才显示单书累计时长，不用 `recordReadingTime` 代替。所选区间的月度排行时长单独列出，它是排行样本，不是全量累计。
- 日历悬停时，优先根据当天笔记和书架最后阅读日期提供的书名线索展示内容，去重后最多显示 5 本。没有线索时，才展示明确标注的月度排行参考，不推算单日逐书时长。
- 阅读时段优先使用完整月度数据，其次是年度数据，最后补充账户总计数据，并标明来源。不同范围的数据不会相加。缺少 24 小时明细时，只展示接口提供的文字偏好。
- 年度分类按书架父类和子类层级匹配，只展示该年有阅读时长或笔记线索的书，不会把当前同类书架全部归入历史年度。
- 笔记分页使用顶层 `count`、`lastSort`，想法分页使用 `bookid`、`synckey`。
- 遇到 `upgrade_info` 时会终止读取，并提示更新本地 weread-skills。启动时会读取本地 skill 版本；如果读不到，则使用 `1.0.5`。
- 开发服务重启或代码新增字段后，旧报告不会自动补齐，需要重新连接并分析。
- 对精确的 `api.deepseek.com` 域名，兼容本地代理 DNS 返回的 `198.18.0.0/15` 映射地址。其他域名仍须通过公网地址检查，HTTPS 证书校验和禁止重定向规则保持不变。

## 隐私与存储

| 数据 | 保存位置与生命周期 |
| --- | --- |
| 微信读书 Key | 默认只保留在页面内存中，也可以主动选择保存到当前浏览器会话 |
| 模型 Key | 只保留在当前页面配置中，不写入后端磁盘 |
| 阅读报告与 AI 结果 | 保存在页面和服务端的短期任务内存中；刷新页面后报告会被清除 |
| 服务端任务 | 客户端完成后会请求删除；停止访问 30 分钟后，遗留任务会被清理 |
| 主题偏好 | 保存在浏览器本地存储中，刷新后仍然保留 |
| 下载的 JSON | 保存在用户本地，包含已抓取的划线、生成结果和提示词，不包含密钥 |

微信读书数据由本地后端从微信读书接口获取。只有在确认发送范围并主动生成 AI 解读后，相关材料才会经本地后端发送给配置的模型服务商。

导出的 JSON 包含个人阅读内容。分享前请检查其中的划线和生成结果。当前不支持导入 JSON 报告。

## 常见问题

**没有模型 Key，能用吗？**

可以。连接微信读书后，就能使用基础阅读报告；完全没有 Key 时，也可以浏览合成示例和四种预置解读。预置内容会标注为演示，不是实际调用模型生成的结果。

**划线很多，生成要等很久怎么办？**

优先选择默认的「精选解读」，并查看生成前显示的请求次数和 token 估算。「全部划线」会随着材料量增加请求次数和等待时间。

**旧报告没有完整划线或单书进度怎么办？**

重新连接并分析即可。旧报告不会自动补充后来新增的字段。当前合成示例包含逐本书架、完整演示句子和逐年书目，可以直接体验主要页面。

**选择了预设，为什么模型仍然调用失败？**

请检查 Key、账号额度、模型是否开通、模型名称、协议和地域是否匹配。火山方舟需要填写自己的模型或接入点 ID；自定义服务还必须满足 HTTPS 和公网地址要求。
